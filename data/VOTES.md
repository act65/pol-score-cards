# Votes, bills & promises — the evidence base for Strength and Authenticity

The datasets that ground the two attributes which cannot be judged from a
speaker's words alone. All are **deterministic** — parsing, a public JSON API
and a handful of documents. No LLM, no inference cost, no subscription quota.

| File | Rows | Built by | Source |
|---|---:|---|---|
| `corpus/divisions.jsonl` | 4,122 party votes | `parse_divisions.py` | the re-scraped Hansard corpus |
| `corpus/bills.jsonl` | 554 bills (53rd + 54th) | `scrapers/bills.py fetch` | `bills.parliament.nz` JSON API |
| `corpus/proposed_bills.jsonl` | 71 ballot bills | `scrapers/bills.py fetch_proposed` | same API, `documentPreset: 3` |
| `corpus/amendment_papers.jsonl` | 632 amendment papers | `scrapers/bills.py fetch_amendments` | same API, `documentPreset: 9` |
| `corpus/strength_ledger.jsonl` | 135 MP rows | `strength_ledger.py` | joins the three above |
| `corpus/manifestos.jsonl` | 14 documents | `scrapers/manifestos.py` | party sites, Wayback, coalition PDFs |
| `corpus/propositions.jsonl` | 212 propositions | `build_propositions.py` | divisions × bills — the Authenticity join key |
| `corpus/oral_questions.jsonl` | 11,082 Q/A pairs | `parse_questions.py` | Hansard question time |
| `corpus/written_questions.jsonl` | 180,939 Q+reply | `scrapers/written_questions.py` | `questions.parliament.nz` JSON API |

```bash
cd data/scrapers
python rescrape_hansard_days.py run --out ../corpus/hansard_v2.json  # ~3-5 h, resumable
python bills.py fetch                  # ~10 min
python bills.py fetch_proposed
python bills.py fetch_amendments
python manifestos.py fetch
python written_questions.py fetch

cd data
python parse_divisions.py run          # -> corpus/divisions.jsonl
python strength_ledger.py run          # -> corpus/strength_ledger.jsonl
python parse_questions.py run          # -> corpus/oral_questions.jsonl
python build_propositions.py run       # -> corpus/propositions.jsonl

python -m pytest                       # from data/ and from data/scrapers/
```

`data/corpus/` is gitignored (it is the HuggingFace publishing staging area), so
these files are regenerated by the commands above rather than committed. Whether
they should join the published dataset via `publish_corpus.py` is an open
decision — the corpus card currently describes raw statements only.

## Where the votes actually are

Not on [voted.nz](https://voted.nz/about/): it tracks **personal (conscience)
votes only** — "party votes (including split votes) are not currently tracked" —
across the 50th–52nd Parliaments, and has no API. For the 54th term that is
close to nothing.

The two official homes for party votes are
[Hansard](https://www.parliament.nz/en/pb/hansard-debates/) (inline in the
debate, which is what we parse) and the
[Journals of the House](https://www3.parliament.nz/en/pb/journals-of-the-house/)
(the formal record). There is also an official
[Parliament Open Data API](https://data.parliament.nz/) that does cover party
votes including split votes — worth revisiting, but it needs a key and its TLS
certificate is currently misconfigured (`data.parliament.nz` serves a cert for
`*.azureedge.net`). We did not need it: **the votes were already in the corpus.**

## `divisions.jsonl` — party votes from Hansard

Hansard prints every party vote in a fixed shape:

```
A party vote was called for on the question, That <question> .
New Zealand National 48; ACT New Zealand 11; New Zealand First 8.       <- Ayes
New Zealand Labour 34; Green ... 15; Te Pāti Māori 4; Ferris.           <- Noes
Motion agreed to.                                                        <- optional
```

One record per division:

```json
{
  "division_id": "2026-05-27-007",
  "date": "2026-05-27",
  "parliament": 54,
  "question": "That the Environment (Disestablishment of Ministry for the Environment) Amendment Bill be now read a third time",
  "type": "third_reading",
  "substantive": true,
  "bills": ["Environment (Disestablishment of Ministry for the Environment) Amendment Bill"],
  "bill_source": "question",
  "ayes": {"parties": {"National": 48, "ACT": 11, "NZ First": 8},
           "members": [], "unresolved_members": [], "total": 67,
           "declared_total": 67},
  "noes": {"parties": {"Labour": 34, "Green": 15, "Te Pāti Māori": 4},
           "members": ["takuta-ferris", "mariameno-kapa-kingi"],
           "unresolved_members": [], "total": 55},
  "abstentions": null,
  "result": "agreed",
  "verdict_line": "Bill read a third time.",
  "flags": ["ayes_labelled"],
  "hansard_headline": "Wednesday, 27 May 2026 — part 8 (2026-05-27)",
  "source_url": "..."
}
```

**Coverage** — 4,122 divisions over 172 sitting days, 2023-07-18 → 2026-05-28.
3,630 are in the 54th Parliament; the rest are late-53rd and carry a
`"parliament": 53` tag. 3,861 have a full tally (the 29 exceptions were
interrupted by points of order, and Hansard prints the tally elsewhere).

| by type | | | by result | |
|---|---:|---|---|---:|
| amendment | 2,696 | | not agreed | 2,457 |
| committee | 592 | | agreed | 1,636 |
| closure | 297 | | unknown | 29 |
| first_reading | 148 | | | |
| third_reading | 98 | | | |
| second_reading | 93 | | | |
| other types | 191 | | | |

`substantive: true` (3,710 of 4,122) marks votes that express a position on
policy — readings, committee stages, amendments, substantive motions. The rest
is floor management (closure, urgency) and should not be read as a policy
position.

### The two scrape defects this exposed (both fixed)

Hansard prints a division as a run of **short** paragraphs:

```
A party vote was called for on the question, That the motion be agreed to .
Ayes 83
New Zealand National 48; Green Party ... 15; ACT New Zealand 11; NZ First 8; Kapa-Kingi.
Noes 34
New Zealand Labour 34.
Motion agreed to.
```

**1. `parse_hansard_day` dropped every `<p>` under 40 characters** as page
chrome. That deleted the `Ayes N`/`Noes N` labels and totals, ~95% of verdict
lines, and **any tally line short enough to fall under the limit** — a small
party's whole side of a vote. That last one is a correctness bug, not a missing
annotation: a division that was really Ayes 83 / Noes 34 was stored as
`noes: null` and flagged `unopposed`.

**2. The same function capped each sitting day at 8 sections.** 141 of 204 days
hit that cap exactly, so the tail of every long day was silently discarded —
and committee stages, where most divisions happen, run late. The corpus was
missing **37% of the Hansard text** (45.0M chars vs 71.8M re-scraped).

Fixes: keep short paragraphs that carry Hansard's own span markup (`HpsItem`,
`CharacterBoldCentred`, …) — page chrome has none; and re-scrape with
`max_sections=99`. Covered by tests in `scrapers/test_hansard.py`.

### What the re-scrape recovered

`rescrape_hansard_days.py` re-rendered the 204 day URLs into a **separate**
`corpus/hansard_v2.json`, leaving the corpus behind the existing 94k scored
examples untouched.

| | before | after |
|---|---:|---:|
| divisions | 984 | **4,122** |
| sitting days with divisions | 154 | 172 |
| divisions with a verdict line | ~47 | 3,710 |
| divisions with a Noes tally | 929 | 3,827 |
| Hansard text | 45.0M chars | 71.8M chars |

Of the 55 divisions previously marked `unopposed`, **41 were simply wrong** —
they had a real Noes tally that the filter had deleted. **21 results changed**,
including outright flips where the surviving tally was the *losing* side and the
positional inference therefore read it as the Ayes:

| Date | Question | Before | After |
|---|---|---|---|
| 2024-03-27 | That the amendment be agreed to | ayes 83, noes none → agreed | ayes 34, **noes 83** → not agreed |
| 2024-05-29 | That the amendment be agreed to | ayes 115, noes none → agreed | ayes 8, **noes 115** → not agreed |
| 2024-11-06 | That the amendments be agreed to | not agreed | **agreed** |

### Labelled vs inferred

With Hansard's labels present the parser **reads** the sides and keeps the
declared total beside the parsed one (`declared_total`, with `tally_mismatch`
when they disagree); the record is flagged `ayes_labelled` (4,055 of 4,122).
Without them it falls back to Hansard's invariant Ayes-then-Noes ordering and
flags `ayes_order_inferred` (67 records — see the fallback note below).

Two further parsing fixes came out of the declared-total cross-check:

- **Tallies can wrap across two paragraphs**, the first ending in `;`. Read
  naively the continuation becomes the *other* side and a whole party's votes
  vanish. Joining wrapped lines — bounded by the declared total, for the cases
  where Hansard omits the closing full stop — took `tally_mismatch` from 64 to 2.
- **Hansard misspells the occasional surname** ("Kapi-Kingi", "Kapa-Kangi").
  These now resolve by close match, but only when exactly one roster name is
  close enough, so two similar surnames can never be conflated.

**The 2 remaining `tally_mismatch` records are errors in Hansard itself**, which
is exactly what the check is for: one line reads `New Zealand Labour 34; New
Zealand Labour 34;` (declared 102, listed 136), and one has a label/tally
off-by-one (declared 49, listed 48).

### The days that would not render

Eight day pages still fail after repeated attempts (a final pass at settle 90s
recovered three of the original eleven). Rather
than lose them, `parse_divisions.py` takes those whole days from the older
corpus via `--fallback_corpus` (67 divisions). Days are never mixed — a day
comes wholly from one corpus — and fallback records keep
`ayes_order_inferred`, so the weaker provenance stays visible and queryable.
Re-running `rescrape_hansard_days.py run` retries them; it is resumable.

### Bill context

Only 9% of division questions name a bill; the rest are procedural ("That the
amendment be agreed to"). Those inherit the most recent bill named in the same
sitting day, tagged `bill_source: "carried_forward"` so the two can be told
apart. 4,064 of 4,122 divisions resolve to at least one bill, across 253 distinct
titles. `bills` is a list because bills split in committee get a single joint
reading (e.g. the Gangs Bill and the Sentencing Amendment Bill).

### Individually-named members

A bare surname in a tally is an MP voting apart from any party — an independent
or a defector. This is the only genuinely per-MP vote signal in the dataset.
They resolve against `mps_roster.json`: Tākuta Ferris (1,448), Mariameno
Kapa-Kingi (1,346), Darleen Tana (163). Two surnames stay unresolved, Kerekere
(256) and Whaitiri (132); both appear only in 53rd-Parliament divisions and are
correctly absent from the current roster.

## `bills.jsonl` — bill outcomes

`bills.parliament.nz` is a Blazor WebAssembly app, so the HTML is empty, but the
JSON API behind it is public and answers plain POST requests — no browser, no
key, no CAPTCHA:

```
POST /api/data/search        list bills, filterable by parliament
GET  /api/data/Bill/{id}     one bill: stage dates, MP in charge, outcome
```

**The `legislation.govt.nz` CAPTCHA is not in the way.** That site holds the
*text* of bills and Acts. Everything needed to ask "did this politician's policy
become law" — who was in charge, which stages it reached, on what dates, and
whether it got Royal assent — is in the API above.

One record per bill: `title`, `bill_number`, `bill_type` (Government /
Member's / Local / Private), `outcome`, `current_stage`, `member_in_charge` +
`member_in_charge_id` (linked to our politician ids), `select_committees`,
per-stage dates, the full `stages` list, and links.

`outcome` is derived, because the API's own `status` field lags — bills that
have had Royal assent are often still marked "Active":

- `enacted` — reached Royal Assent.
- `terminated` — status Terminated without assent: defeated, withdrawn,
  discharged or lapsed.
- `in_progress` — still before the House.

The fetch covers **parliaments 53 and 54 by default**. The API files a bill under
the parliament that introduced it, so bills carried over from the 53rd are still
being voted on in the 54th; fetching only 54 leaves holes in the join.

554 bills in total: 290 filed under the 54th Parliament, 264 under the 53rd.
The delivery gradient is already the Strength signal in raw form — a Government
bill is overwhelmingly likely to become law, a member's bill overwhelmingly
likely not to:

| Type | Bills | Enacted | Terminated | In progress |
|---|---:|---:|---:|---:|
| Government | 431 | 348 | 16 | 67 |
| Member's | 107 | **22** | 52 | 33 |
| Private | 10 | 7 | 1 | 2 |
| Local | 6 | 5 | 1 | 0 |

Restricted to the 54th Parliament only: Government 232 bills / 165 enacted;
Member's 53 / **6**.

Every bill names an MP in charge. 472 of 554 link to a politician id; the 82
that do not are all ministers of the previous government who left in 2023
(Kiritapu Allan, Andrew Little, Michael Wood, Nanaia Mahuta …), correctly absent
from the current roster. Within the 54th Parliament alone the link rate is
290/290.

## Joining the two

Match `divisions[].bills[]` to `bills[].title`, normalised (lowercase,
alphanumeric only). **4,060 of the 4,064 bill-naming divisions join** (99.9%),
across 244 distinct bills; **3,232 divisions are both substantive and joined in
the 54th Parliament** — that is the usable evidence set for stance work. The 4
stragglers are cosmetic (a title-case variant, a Hansard "Correction—" prefix).

Fetching only parliament 54 drops the join to 88%; the carry-over bills from the
53rd account for nearly the whole difference, which is why `bills.py fetch`
defaults to both. Recompute at any time with:

```bash
cd data && python -c "
import json, re, collections
key = lambda t: re.sub(r'[^a-z0-9]+', '', (t or '').lower())
idx = {key(json.loads(l)['title']) for l in open('corpus/bills.jsonl')}
d = [json.loads(l) for l in open('corpus/divisions.jsonl')]
named = [x for x in d if x['bills']]
joined = [x for x in named if all(key(b) in idx for b in x['bills'])]
print(f'{len(joined)}/{len(named)} bill-naming divisions join')"
```

## Strength: the legislative work ledger

`strength_ledger.py` joins three sources into one row per MP —
`corpus/strength_ledger.jsonl`:

| Source | 54th Parl | Signal |
|---|---:|---|
| `bills.jsonl` — bill in charge | 290 bills | delivery |
| `proposed_bills.jsonl` — lodged in the members' ballot | 71 | initiative, independent of ballot luck |
| `amendment_papers.jsonl` — Amendment Paper in own name | 632 | drafting work on others' bills |

```bash
cd data/scrapers && python bills.py fetch_proposed && python bills.py fetch_amendments
cd data && python strength_ledger.py run
```

Widening past bills-in-charge is what makes Strength scorable at all:

| Evidence admitted | MPs covered (of 135) |
|---|---:|
| bill in charge only | 75 |
| \+ ballot bills | 117 |
| \+ amendment papers | **121** |

**No evidence is not low Strength.** 14 MPs have nothing, and they carry
`insufficient_evidence: true` and no score rather than a zero — an MP with no
bills has not failed to deliver, they had no opportunity. Those 14 are three
different things and should not be treated alike: MPs who have left but linger
on the stale roster (the reconciliation task in `TODOs`), structural roles that
never hold bills (the Prime Minister and the Speaker are both in this list), and
genuine backbenchers with no legislative output. Only the third is a real
finding.

**Amendment Papers count as distinct bills engaged, not raw papers.** Tabling
scores of near-identical amendments during a committee stage is a filibuster
tactic, not scores of units of work:

| MP | Papers | Distinct bills |
|---|---:|---:|
| Lawrence Xu-Nan | 111 | 4 |
| Lan Pham | 56 | 3 |
| Lemauga Lydia Sosene | 25 | 1 |
| Ricardo Menéndez March | 42 | 9 |

**The ledger writes no score, on purpose.** It emits components —
`delivery_rate` (enacted ÷ *resolved* bills in charge, `null` when nothing has
resolved, so pending never reads as failure), `initiative`, `engagement` — and
leaves weighting to the scoring step, because the weighting is where the
government/opposition confound bites:

| | n | mean delivery_rate | mean engagement | mean initiative |
|---|---:|---:|---:|---:|
| Government | 70 | **0.91** | 4.2 | 4.5 |
| Opposition | 65 | **0.28** | 1.8 | 1.2 |

Weighted on delivery alone, Strength is a government detector. That is partly
real — ministers genuinely can deliver and backbenchers cannot — but it must be
a deliberate choice, and checked the way the subject-attribution bias was.

## Manifestos & coalition agreements (the promise side)

Because the vote record is party-level, the promise side should be too.
`scrapers/manifestos.py` captures a small curated registry of documents into
`corpus/manifestos.jsonl` — each one live (the 2026 platform) and, where useful,
from the closest Wayback snapshot to the 2023 election (what they campaigned on
to win this term):

```bash
cd data/scrapers && python manifestos.py fetch      # ~377k chars, 14 documents
python manifestos.py registry                        # list the documents
```

**Coalition agreements are the strongest promise set we have** — signed, dated,
numbered, with published quarterly progress. Both extract cleanly as PDFs
(National/ACT 28k chars, National/NZ First 31k).

**Party policy platforms are partial, and the tool says so.** Each capture
records `pages`, and anything thin is reported as a problem rather than passed
off as a manifesto. Current state: Te Pāti Māori 2023 (185k) and the Green 2026
platform (66k) are rich; National and ACT's 2023 snapshots are thin (~3.5k);
**NZ First is JS-rendered and yields almost nothing** (650 chars). Two fixes,
both cheap: route the thin ones through the existing Playwright path, or add the
direct manifesto PDF URL to `REGISTRY` — it is a one-line entry per document.

**Snapshot dates are recorded, never assumed.** The Wayback availability API
returns the *closest* snapshot, which can be years off; the Green policy page's
nearest capture to the 2023 election is July 2025. Records carry
`snapshot_date`, `snapshot_drift_days` and `stale_snapshot: true` past the
tolerance, so a 2025 page can never be silently used as a 2023 promise.

## Authenticity: the proposition vocabulary

`build_propositions.py` turns the divisions and bills into **212 canonical
propositions** — the closed vocabulary both sides of the Authenticity join
normalise to.

Free-text matching does not work here. Bill titles are bureaucratic while
statements are colloquial, and — fatally — embeddings capture *topic*, not
*stance*: "I will always defend renters" and "renter protections are red tape"
sit almost on top of each other, and stance is the entire question. So a
statement is tagged with a proposition id and a stance, and Authenticity becomes
a table lookup.

Each proposition records how every party voted, weighted so decisive stages
dominate — a third reading is a settled position, a committee-stage clause vote
is not, and opposition parties routinely support individual clauses of bills
they vote against overall. Amendments carry **zero** weight: voting down
someone's amendment is not a stance on the bill.

| stance confidence | n | meaning |
|---|---:|---|
| high | 125 | decided at second or third reading |
| medium | 75 | first reading only |
| low | 12 | committee or motion votes only |

Party stance counts across the 212 (support / oppose / mixed):

| Party | n | support | oppose |
|---|---:|---:|---:|
| National | 209 | 173 | 35 |
| ACT | 209 | 167 | 42 |
| NZ First | 185 | 164 | 20 |
| Labour | 210 | 95 | 113 |
| Green | 210 | 64 | 145 |
| Te Pāti Māori | 195 | 48 | 146 |

`member_positions` carries the individually-named dissenters separately (Ferris
66 propositions, Kapa-Kingi 47, Tana 22) — the only genuinely per-MP vote
evidence in the dataset.

## Forthrightness: question/answer pairs

Evasion is a **relation between a question and an answer**; it cannot be seen in
an isolated sentence, which is what the rest of the pipeline scores. So the
pairs are built first, deterministically, and only the judgement is left to a
model.

### `oral_questions.jsonl` — Hansard question time

`parse_questions.py` recovers **11,082 question/answer pairs** across 186
question-time days (2,371 primary + 8,711 supplementary). Hansard changed house
style mid-term and both are handled:

```
Question No. 1—Prime Minister                       (to 2025: numbered, portfolio)
1. Rt Hon CHRIS HIPKINS (…) to the Prime Minister: Does he stand by …?

Question No. 1                                      (2026: bare, timestamped)
DAN BIDOIS (National—Northcote) (14:44) to the Minister of Finance : Will …?
```

Interjections from other members ("Answer the question"), chair turns, and the
asker's own points of order are dropped — a point of order is procedure, and
counting it as a supplementary pairs the Minister's real answer with the wrong
text; a Minister answering "on behalf of" a colleague resolves to whoever
actually answered. 99% of responders link to the roster; the rest are
53rd-Parliament MPs. Most questioned: Luxon (2,145), Willis (1,307).

### `written_questions.jsonl` — the cleaner signal

`scrapers/written_questions.py` pulls written questions and ministerial replies
from `questions.parliament.nz`. No diarisation, no interjections: one MP asks in
writing, one Minister replies in writing, both texts published and dated.

Three API constraints, all handled and all discovered the hard way:

- It is a **different API shape** from `bills.parliament.nz` — `searchTab` /
  `members` / `ministers`, not `documentPreset`. Sending the bills shape 400s.
- **Deep pagination 500s.** Walking the unfiltered result set dies at about
  page 102 (~101,000 rows), so a parliament cannot be paged in one sequence.
- **`dateFrom` and `dateTo` only filter when sent together.** Either alone is
  silently ignored and returns the unfiltered ~181,000 count — which is what
  made the first attempt try to page the whole set. With both, the filter works,
  so the fetch slices **one month at a time** and every sequence stays a few
  pages deep.

The fetch **appends after each month and resumes** from what is on disk. An
earlier version buffered everything and wrote at the end; the 500 at page 102
discarded 100,989 rows. Re-running picks up where it stopped.

The full reply text arrives in the listing, so there are no per-question detail
calls. Askers come back as GUIDs and are named via `searchFilters`.

**Score distinct questions, not raw ones — written questions are bulk-filed.**
This is the amendment-paper filibuster all over again, and larger. Of 180,939
questions there are only **56,482 distinct templates (31.2%)**, and the top 20
templates alone account for 18% of everything asked. One Verrall template —
*"in the Minister's departments, ministries and agencies for which savings have
been identified…"* — was filed **1,763 times** across 31 ministers.

Two consequences, both must be designed for:

- *For the asker*: 20,349 questions is not 20,349 distinct inquiries. Raw counts
  would rank bulk-filers as the most diligent MPs in Parliament.
- *For the Minister (Forthrightness)*: the same boilerplate reply to 1,763
  identical questions is **one** evasion event, not 1,763. An evasion rate over
  raw questions is dominated by whichever portfolio got template-bombed.

So Forthrightness is computed per **distinct question template** — normalise
numbers and whitespace out, group, and score the group — exactly as Strength
counts distinct bills engaged rather than amendment papers filed. This also
makes the LLM pass affordable: 56k templates instead of 180k questions,
and a sample of those.

**A pending question is not a non-answer.** An unanswered question carries the
placeholder `"Reply due: 10 Aug 2026"` rather than an empty field; scoring that
as a reply would read as evasion. Records carry `answered` and, where a Minister
replied only with a document, `attachment_only` — neither may count against a
Minister as a dodge.

## What this data can and cannot support

**It is mostly a party-level signal.** NZ party discipline is near-absolute, so
a party vote attributes one position to all 48 National MPs. Genuine per-MP
variance exists only in the individually-named members above and in conscience
votes. Any MP-level score derived from these votes is really *"did your bloc do
what you said"* — that has to be stated in the methodology, not buried.

**Report against the party-line baseline.** A model predicting NZ votes from
party alone is right ~97% of the time. Any accuracy number without that baseline
next to it is meaningless.

**Government and opposition are not symmetric.** Opposition MPs vote against
most government bills because that is their role, and only ministers and
members in charge of a bill have any lever to deliver one. Strength scored
without a delivery-scope gate would repeat the subject-attribution error
documented in `attribute-extraction/EVALUATION.md` in a new form. Check party
means before and after, the way that analysis did.
